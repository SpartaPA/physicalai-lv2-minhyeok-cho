# 실험 중단 및 재개 기록 — 2026-10-13

## 하드웨어 및 모터 구성
- Raspberry Pi와 OpenCR 1대를 사용하며, 모터 4대가 연결되어 있음.
- DYNAMIXEL 통신 속도: 1000000 baud, Protocol 2.0.
- 활성 조향 모터: XM430-W350, ID 11.
- 활성 구동 모터: XM430-W210, ID 1.
- 비활성 모터: W350 ID 12, W210 ID 2. 토크 해제 상태로 유지.
- 모터 4대의 Secondary ID는 모두 255로 확인됨.
- 전원: 12 V / 5 A 고정 출력 어댑터.
- 외부 전류 센서 및 조절 가능한 전류 제한 장치 없음.

## 펌웨어 상태
- 소스: firmware/two_motor_telemetry/two_motor_telemetry.ino
- 응답 버전: opencr-two-motor-telemetry-v3
- 재설정 후 INIT 명령으로 초기화해야 함.
- Secondary ID 읽기에 uint8_t 변환을 적용함.
  - 라이브러리가 255를 부호 있는 값 -1로 반환하는 문제를 처리함.
- 업로드한 바이너리의 SHA256:
  e5549922cc62478c9e34d6aac1d26a54a89ca776ef5b299ddd36b3e130a35130
- 부팅 시 INIT를 기다리며 모터 설정을 자동으로 변경하지 않음.
- INIT는 재설정 후 한 번만 시도할 수 있음.
- 오류 발생 후에는 재설정과 초기화를 거쳐야 다음 시험을 진행할 수 있음.

## 아직 확인하지 않은 내용
- 하트비트 타임아웃 시험 명령은 제공되었으나 결과는 확인되지 않음.
- 재시험 전에 heartbeat_timeout_idle 로그가 생성되어 있는지 확인할 것.
- RUN STEER, RUN DRIVE, RUN BOTH를 이용한 동작 시험은 아직 확인되지 않음.
- armed-IDLE 시험 중 실제로 움직임이 보였는지는 별도로 기록되지 않음.
- armed-IDLE 시험의 STATUS 요청 이전에 불완전한 직렬 출력이 있었음.
  - 해당 줄은 분석에서 제외할 것.
  - 원인은 아직 확인되지 않음.
- OpenCR의 전원 비활성화 신호가 실제 모터 전원을 차단하는지는 검증되지 않음.
- 모터 전류 텔레메트리는 부하의 대리지표이며,
  어댑터 또는 OpenCR 전체 입력 전류를 측정한 값이 아님.

## 종료 시 수행할 작업
아래 항목은 종료 절차이며, 수행 완료를 의미하지 않음.

1. 메커니즘을 지지한 상태에서 OpenCR의 12 V 전원과 배터리를 분리.
2. 실행 중인 시험 스크립트가 있으면 종료.
3. OpenCR USB 케이블 분리.
4. 소스, 실험 기록 및 이 문서를 Git에 커밋하고 원격 저장소에 푸시.
5. Raspberry Pi를 정상 종료한 다음 전원 분리.

## 재개 순서
1. 모든 전원이 분리된 상태에서 배선과 메커니즘 지지 상태를 확인.
2. USB를 연결하고 HELLO 응답에서 펌웨어 v3를 확인.
3. 12 V를 연결한 뒤 powered_init 진단 스크립트를 실행.
4. INIT,OK와 STOP 이후 ACK,DISARMED를 확인.
5. 다음 시험은 IDLE 상태에서 하트비트를 중단하는 타임아웃 시험.
6. 타임아웃 시험을 확인하기 전에는 RUN 동작 명령을 보내지 않음.

## 해석 시 주의
- STOP은 정상 경로에서 모터 토크를 해제하며, 12 V 전원을 차단하지 않음.
- 토크 해제 상태에서는 모터가 자세를 능동적으로 유지하지 않음.
- 오류 이후 MOTORS_MISSING은 초기화 유효 상태가 해제되었다는 뜻일 수 있으며,
  반드시 모터가 물리적으로 분리되었다는 뜻은 아님.
